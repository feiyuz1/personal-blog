# 用户系统规划（暂缓）

## 当前决定

当前阶段不开发本地用户注册、密码登录和邮箱找回密码功能。

原因：博客仍处于内容建设阶段，本地账号系统会额外带来注册风控、密码安全、账号恢复、隐私处理和垃圾评论治理等持续维护成本，现阶段收益有限。

## 当前评论策略

- 保留评论审核机制；
- 评论接口保留限流；
- 后续如继续开放匿名评论，应增加验证码以减少垃圾内容；
- 如评论维护成本过高，可暂时关闭评论，仅保留邮箱和 GitHub 联系方式。

## 后续推荐方案

优先采用 GitHub 身份体系，而不是自建账号密码系统。

### 方案 A：giscus（优先考虑）

- 使用 GitHub Discussions 承载评论；
- 读者使用自己的 GitHub 账号登录和评论；
- GitHub 负责密码、二步验证、账号恢复和安全风控；
- 不在本站保存用户密码或邮箱；
- 适合面向 C++、图形学、Unreal Engine 等技术读者的博客。

接入前需要：

1. 创建或选择一个 GitHub 仓库；
2. 开启该仓库的 Discussions；
3. 在 giscus 配置仓库、分类与页面映射；
4. 将生成的配置嵌入文章详情页。

### 方案 B：GitHub OAuth 登录 + 本地审核

适用于需要保留本站评论审核后台、封禁能力与评论数据的场景。

- 用户使用 GitHub 登录；
- 首次登录创建本站用户记录，默认状态为 `PENDING`；
- 管理员审核后将用户设为 `ACTIVE`，才允许评论；
- 本地仅保存 GitHub 用户 ID、用户名、头像、状态和角色；
- 不申请或保存用户邮箱，不保存用户密码；
- 用户被封禁后禁止登录评论。

GitHub OAuth 回调地址建议使用：

```text
https://www.feiyulab.xyz/api/auth/github/callback
```

## 不推荐方案

- 自建用户名/密码体系：没有可靠邮箱服务时无法安全地自助找回密码；
- 手机验证码：需要短信服务、费用与合规维护；
- 未验证邮箱的开放注册：容易被垃圾账号和自动化脚本滥用。
